Concepts & Code Map

I made this page as the main reference for the project. It explains what the system is trying to solve, how the pieces fit together, and where each part lives in the codebase.

Purpose of the Project

The idea behind this project is simple: I wanted a small edge device that can test a battery, log what is happening, and explain the result without sending anything to the cloud. The Raspberry Pi handles the measurements and the dashboard. The battery calculations come from normal formulas and rule checks. The language model is there to make the final result easier to understand, not to guess the measurements.

Core Concepts

Edge Intelligence
Local sensing + local reasoning
The Pi does the useful work locally instead of depending on an external API.
Telemetry
Voltage, current, power, temperature
These are the raw readings the rest of the project depends on.
Capacity Integration
mAh and Wh over time
The health estimate starts by adding up current flow across the session.
LLM Report
Explanation, not measurement
The model turns the computed facts into a short readable report.

Code Walkthrough

How I split up the code
FileWhat it handlesImportant pieces
edge_battery_ai/server.pyThis is the main app entry point. It serves the website, exposes the JSON API, and starts the background loop that keeps collecting samples.lifespan, _collect_loop, /api/status, /api/summary, /api/report
edge_battery_ai/sensors.pyThis keeps hardware-specific code away from the rest of the app. Simulator mode and INA219 mode both return the same reading shape.Sensor, SimulatedBatterySensor, Ina219Sensor, build_sensor
edge_battery_ai/storage.pyThis is the local data layer. It creates sessions, saves readings, and gives the analytics code the samples it needs.TelemetryStore, create_session, insert_reading, latest_readings
edge_battery_ai/analytics.pyThis is where the actual battery logic lives. It calculates capacity, energy, cycle throughput, health status, and warnings.summarize_session, diagnose, _integrate_capacity
edge_battery_ai/llm.pyThis file talks to Ollama or llama.cpp. It builds a careful prompt from the measured facts and falls back to a normal report if the model is not running.BatteryReportGenerator, build_prompt
edge_battery_ai/models.pyThese are the shared data shapes. Keeping them typed makes the API and the calculations easier to reason about.TelemetryReading, SessionSummary, AiReport

edge_battery_ai/static/app.jsThis powers the interactive parts of the site: the diagram, charts, concept cards, and live model report button.draw, loadTelemetry, drawTelemetry, showConcept
training/*.pyThis is for later if I want to fine-tune the model on my own battery report examples. The project does not need this to work.build_dataset.py, finetune_lora.py

Design Note

I kept the measurement logic separate from the language model on purpose. Battery health should come from the readings and the formulas, because those are things I can test and explain. The model sits at the end of the pipeline and turns the results into a short diagnosis that is easier to read.
